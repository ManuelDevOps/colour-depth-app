# Colourful visual refresh

Branch `feat/pixel-color-app-v2` from base `4341802`. Visual-only change for a child audience (about 11–16, secondary school); no layout, DOM or behaviour change.

## Specs
- **S1 — Colourful, child-friendly look.** The user asked (verbatim): "esta aplicacion es para niños y el diseño sin embargo es muy sobrio. me gustaria algo mas colorido pero sin vambiar la posicion y funcionalidades de los elementos, solo quiero un cambio visual. Primerop me gustaria crear a wireframe para tener una idea de lo que podrias proponer y luego lo aplicamos a la app". Warm light background, a friendly accent per panel, rounded headings, candy depth pills, playful ON/OFF switches and round header badges, keeping WCAG AA contrast, a visible focus ring, reduced-motion support and no colour-only signals.
- **S2 — Positions and functionality unchanged.** Every element keeps its original box at every viewport, and switches, depth, help, the colour picker and ES/EN behave exactly as before. The pixel and bulbs keep their data colours, the pixel keeps a neutral frame and R/G/B accents stay red/green/blue. The visible ON/OFF switch faces stay as they are.
- **S3 — Mockup first, apply after approval.** A grey wireframe would look the same as today's layout, so the "wireframe" is a working mockup over the real app (`design/colourful-mockup.html` + `design/colourful-theme.css`). Nothing is applied to `src/` until the user approves.
- **S4 — Title "Colour Depth App" and subtitle.** The app title (heading and document `<title>`) is exactly "Colour Depth App" in English and Spanish. Directly under it, a visually secondary subtitle reads exactly "Let's paint the pixel!" in English and "¡Vamos a pintar el píxel!" in Spanish and switches with ES/EN.
- **S5 — Centred edit panel with narrower fields.** In the result panel's RGB/HEX editor, the Red/Green/Blue and HEX labels and the values inside the inputs are centred. The RGB inputs are sized for 3 digits and the HEX input for `#RRGGBB`. Each label stays on one line, and the editor content is centred in its column with no horizontal overflow at any viewport. Input height, error messages, aria attributes and editing behaviour are unchanged.
- **S6 — Colour count beside the depth buttons.** The user asked (verbatim): "esta perfecto, solo un caambio mas, muy facil. Necesito que a la derecha del panel donde se seleccionan el numero de bits, aparezca una cifra mostrando el numerop de colores que se pueden mostrar con esos bits, por ejemplo 1 bits serian 2 colores, etc. Entendiste?" To the right of the depth buttons, a badge shows 2^bits for the selected depth: "2 colours", "8 colours", "256 colours", "16,777,216 colours" in English and "2 colores", "8 colores", "256 colores", "16.777.216 colores" in Spanish. It updates on every depth change, including automatic ones from RGB/HEX editing and the colour picker, and on ES/EN. The depth buttons keep their exact boxes on desktop and tablet; where the badge does not fit to the right, it sits directly below the buttons, with no horizontal overflow. It is a polite live region (`aria-live="polite"`), never a focusable control, with contrast ≥ 4.5:1.
- **S7 — Footer and README copyright.** The user answered (verbatim): "pon en la app algo asi como (c)2026 y es suficiente para la app luego en readme el resto, ponle tambien un enlace para mi github un icono linkeado al repo de la app". At the end of the app card, a small footer shows exactly "© 2026" and, next to it, a GitHub icon link to `https://github.com/ManuelDevOps/pixel-colour`. The icon is an inline SVG with `aria-hidden="true"` and `focusable="false"`. The link opens with `target="_blank" rel="noopener noreferrer"`, and its accessible name is "View the source code on GitHub" in English and "Ver el código fuente en GitHub" in Spanish, switching with ES/EN. Contrast is ≥ 4.5:1, the focus ring is visible and the link target is at least 44×44 px. The footer only adds content at the end, with no horizontal overflow. In `README.md`, the title is "Colour Depth App", followed by "Let's paint the pixel!" and "Created by Manuel Giraldo Carro.", and a final "Copyright" section reads "Copyright © 2026 Manuel Giraldo Carro." No license text or LICENSE file is added, because the user is still choosing the license.
- **S8 — Taller edit fields.** The RGB and HEX inputs are at least 44px tall (40px before), keeping their widths, centring and behaviour. This replaces the "input height unchanged" part of S5.

## Decisions
- **CSS-only override.** The theme is layered after `src/styles.css` with the same selectors and changes only colours, backgrounds, radii, shadows, fonts and absolutely positioned decorations. Thicker-looking edges and rings come from `box-shadow`, never from wider borders, so no box changes size.
- **Neutral frame around the pixel.** The result panel uses neutral `#f7f7f8` with only a yellow edge. The swatch rule (white 5px border and shadow), the bulbs, the white channel cards behind them and the wires are left untouched, so the surroundings do not bias colour perception.
- **D-title — Brand title is not translated.** "Colour Depth App" is a brand name, so it is the same in English and Spanish.
- **D-subtitle — Translated subtitle.** "Let's paint the pixel!" / "¡Vamos a pintar el píxel!" sits under the title in the rounded heading font, bold, at `clamp(1rem, 1.6vw, 1.25rem)` (below the title's size), in magenta `#c2185b` (5.78:1 on `#fffdf9`).
- **D-footer — Footer inside the card.** The footer is the last visible child of `<main class="explorer">`, so it sits inside the card under the switches and does not change any box above it.
- **D-count — Badge beside, then below at 760px.** Measured at 24 bits, the badge overflowed the page from 561px to about 700px, so the "below" fallback uses the existing 760px breakpoint rather than 560px. From 761px up it fits beside the buttons inside the content box. It is a lilac sticker (`#5a189a` on `#f1eaff`, 8.84:1) with no hover look, because it is not a control.
- **No external fonts.** Headings use `ui-rounded, "Arial Rounded MT Bold", "Segoe UI", system-ui, sans-serif`, with no web fonts, CDNs or images. Body text and font weights are unchanged so text metrics stay the same.
